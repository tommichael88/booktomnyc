## 3. Architecture, as it is today (not as the target)

- **The page.** `qr.html` is one file. Five modules are inline blocks (`pricing_engine`, `orchestrator_engine`, `UIRenderer`, `cart_logic`, `AppController`); four are files in `modules/` loaded by `<script src>` (`trace`, `nlp_engine`, `appReducer`, `store`). For an inline module the block in `qr.html` is the source. The `*.js` files of the same names at the repository root are **generated, git-ignored reference copies** (`node test_harness/extract_modules.js`; rerun after any `qr.html` edit). `purity_audit.json` is a derived but tracked output.
- **Two catalogs while the dual-source transition is open (T175).** `ssot/btnyc_source.json` is the **entity-first authored source** and is authoritative (entities own their questions, uncertainty classes and services; services are entity + action + modifiers; ids everywhere; confidence, retirement and recovery are authored); `btnyc.json` is what the runtime and the compiler still read and is kept in parity with it (`node test_harness/tools/entity_first/project_legacy.js --check`). A change `btnyc.json` can express is made in both in one commit; a change it cannot express (a weight, a scope, a retirement, a decomposition) is made in the source only. After a source change run `derive_graph.js` and `report.js --write` (their `--check` modes are in the suite). The rules are in `ssot/TRANSITION_DUALSOURCE.md`. `migrate_legacy.js --write` refuses to overwrite an edited source. The next bullet describes `btnyc.json`, not the source.
- **Source, artifact and lifecycle (T176, `ssot/ENTITY_FIRST_DESIGN_NOTE.md` section 3.1; #212).** The Charter's end state is: authored knowledge in `btnyc_source.json`, edited through the CMS; **`btnyc.json` is the derived runtime artifact** the engine consumes, carrying a `$source` provenance reference; the runtime never reads the source or a hybrid. Today (**P1**): the source is authoritative and is edited as JSON by hand (no tool or CMS edits it); `btnyc.json` is the legacy hybrid, a **mirror** held to the source by `project_legacy.js --check`, and is still what the runtime reads; `ssot/derived/btnyc_graph.json` is a pre-publication candidate with no runtime consumer, **written since T177 only by `publish.js`** (eight gates; it never writes `btnyc.json`). At completion (**P2**) `btnyc.json` is written only by that publish step, retargeted (not done), and the legacy authoring tools retire; the cutover is one commit. **S1 to S5 cannot be applied as patches to the legacy `btnyc.json`** (the parity check fails them by design); `ssot_patch.js` then `splice_compiled.py` stay intact for the legacy shape and edit the mirror, never the source. Ids are frozen by `ssot/migration/id_register.json` (`id_register.js --check`; an id leaves only by a written retirement). `transition_status.js` checks the five completion conditions and names the unmet ones.
- **The catalog (`btnyc.json`).** `btnyc.json` (about 45,000 lines) is **service-first, not entity-first**: 76 `services`, 82 `dynamic_services`, 135 `intake_modules`, 59 `smart_tags`, 39 groups with `routing_archetypes`, plus `checkout_states`, `pricing_archetypes`, `global_rules` and compiler-owned `compiled`.
