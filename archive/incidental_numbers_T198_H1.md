# T198 H1 — a number that is not a count is no longer read as the job's quantity

**Before (main `4b714e5`).** `extractQty` (modules/nlp_engine.js) fell back to the first bare number in the text and clamped it to 99. "replace light bulb model 4500" -> qty 99 on a dynamic service -> $6,435 / 60 min; "install a dimmer switch model 4500" -> $6,435. Model, serial and part numbers, room and apartment numbers, floors, years, dates, times, prices, dimensions and ids all reached that fallback.
**After.** The same text is read for quantity only after the incidental numbers are masked, by the same function (no second parser): designators (model, serial, part, sku, room, apt, floor, unit, zip, order, no. ...), `#N`, money and percentages, times, dates and fractions, `N x N` / `N by N`, month + day, ages and durations in years/months, unit-bearing measurements (mm, sq ft, gal, watts, volts, amps, btu, lumens, psi, degrees, inch marks), ordinals, `3-way`, letter-digit and digit-letter ids (`KD-4500`, `rtx3080`, `4B`), numbers of three or more digits and comma thousands. Then the old order is kept: a number before a count noun (tiles, items, pieces, units, doors, fixtures, signs, shelves, outlets, switches), `replace|install|fix N`, number words, and a bare number only when a word follows it ("assemble ikea malm dresser 4 drawers" = 4). When no quantity can be established the answer is 1: a dynamic service then asks its own `global_quantity` question and the card's quantity control stays available. `extractStatedCounts` (#249) reads the same masked text; its separate designator list is gone.
**Decisions (recorded, measured).**
- A trailing bare number ("flat-pack furniture assembly 12") is ambiguous and now reads as 1 (42 of 3,344 numbers-corpus phrases; all were of that shape, e.g. $650 -> $54). The customer can say "12 pieces", or set the quantity on the card.
- A count of 100 or more reads as 1 ("replace 100 bulbs", "replace 150 outlets"): three digits is far likelier to be a model or part number than a count of jobs, and 99 was already a ceiling that invented a number. Not a clamp of large numbers to 1: 2..99 keep working.
- Hours are quantities for the hourly services ("2 hours of furniture repair" = 2), unchanged.
**Measured (same phrases, main vs this tree).** Default typed corpus 357: 0 changed; wide corpus 7,803: 0 changed; service tile states 23,409 identical; golden master 2,988: 0 differ. Numbers corpus (3,344 phrases): 349 incidental-class phrases changed, 345 price down, 0 up, 0 service changes; 42 legitimate-class phrases changed, all trailing bare numbers (above). Every service name x 31 incidental suffixes (2,356 phrases): `extractQty` = 1. Count corpus (275, #249): one phrase changed, "install a dimmer switch model 4500" 6435/60 -> 65/60; the #249 results are otherwise identical.
**Tests.** New `verify_incidental_numbers_not_quantity.js` (50 checks, through the real workflow: service, quote, units, open questions; legitimate quantities; #249 preserved; planted original reader fails checks 6, 6.1, 6.2). Existing quantity tests pass locally (jsdom ones run only in CI).
