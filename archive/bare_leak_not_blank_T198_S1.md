# T198 S1 — a leak with no named fixture is answered, not ignored

**Defect (found by looking at the real page, not the engine).** Typing "water leak", "I have a leak", "leak", "my house is leaking" or "roof leak" produced **no response at all**, and the page threw `Cannot read properties of undefined (reading 'units')`. Cause: the plumbing category has a Diagnostic dynamic definition and an Install one but **no Repair one**; a repair request that names no fixture (so no group) therefore fell to the catastrophic fallback (a vetoed `legacy_flow` route with no `quantity`), and `sqAnalyze` read `route.quantity.units` unguarded. "Pipe leak" and "toilet problem" worked only because they name a group.
**Change (owner: the inline orchestrator in `qr.html`).** (1) In the last-resort category branch of entity resolution, a Repair request whose category has no Repair definition uses that category's Diagnostic definition (it asks which fixture); existing services' dynamic enrichment is untouched. (2) `sqAnalyze` reads `route.quantity?.units ?? 1`, so a route without a quantity cannot throw.
**After.** The leak phrasings show the on-site quote panel: "Answer a few more questions" (asks "Which plumbing fixture needs attention?": sink or faucet, toilet, shower or tub, garbage disposal, water line) or "Book an on-site diagnostic" ($85, credited toward repair). No page error. Faucet leak, leak under the sink and the other named-fixture routes unchanged.
