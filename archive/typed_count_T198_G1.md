# T198 G1 (#249) — a count the customer typed answers the count question that asks about it

**Before (main `890afa2`).** "replace 3 light bulbs" -> Led Bulb Upgrade, $20 / 30 min, `qty` 3 extracted, and "How many light bulbs need attention?" still open: the same question and quote as "replace 1 light bulb" and "replace 6 light bulbs". 18 services ask a count question (the ledger said 29: the others are not reachable from their own tile); none of the 18 moves the price when an answer is tapped (workflow and session paths both measured).
**After.** The option whose authored `count_range` contains the stated count is the answer: 1 -> "1 bulb", 2 and 3 -> "2-3 bulbs", 4 to 6 -> "4-6 bulbs". On the page the chip shows selected and can be changed. Price, minutes, checkout state and the units priced (1) are unchanged.
**What changed (and where).** Data: `count_range: {min, max?}` on all 18 services' count options (authored on the option; never read from a label; ranges of a question do not overlap; a band shadowed by the next band ends where that one starts: "3 or more outlets" before "4 or more outlets" is authored 3..3). Schema + `migrate_legacy.js` / `project_legacy.js` / `validate_source.js` (V-OPT-COUNT-RANGE, with two mutants in `verify_entity_first_validator.js`). Parsing: `extractStatedCounts` beside `extractQty` in `modules/nlp_engine.js` (a number or number word 1..99 with the next two words; not a measurement, compound, ordinal or designator such as "model 4500"). Logic: `orch_apply_typed_counts` beside `orch_apply_path_facts` in `qr.html`, called in the compose step. It answers only an unanswered item_count_template question, only from a count said right before one of the question's own item nouns, only if every such count is the same number, only if exactly one range contains it. The customer's own answer is never replaced.
**Measured (same phrases, main vs this tree).** Default typed corpus 357: 0 changed. Wide corpus 7,803: 0 changed. Service tile states 23,409: all identical. Golden master 2,988: 0 differ. Count corpus (`archive/typed_count_corpus_T198_G1_diff.txt`; 18 services x counts 1..20 + 23 hand phrases = 275): 0 price, minutes, state, service or routing changes; 235 change only in the open-question list (the count question is answered); 19 still ask, all by design: 7 or more bulbs (no authored range covers it), 0, "2 bulbs and 4 bulbs" (two counts), "model 4500", a count after the noun ("light bulbs 3").
**Typed vs catalog.** For all 18 services x every count answer (77), the typed count quotes exactly what the tapped answer quotes and prices one unit (`verify_typed_count_answers_question.js` 5). The guided builder resolves a dynamic entity and never reaches the curated count question, so it has no counterpart.
**Not done / found, not fixed.** (1) The count answers carry authored fees (e.g. "2-3 bulbs" +$15 / 15 min, "4-6 bulbs" +$30 / 24 min) that no quote charges today (the service lists no `modifier_ids`; unchanged by this slice, so a typed count prices exactly what a tapped one does). If those fees are ever wired, a typed count will select the right band by its range. (2) `extractQty` still turns "replace light bulb model 4500" into qty 99 on a dynamic service ($6,435): a pre-existing quantity-extraction defect this slice does not touch; the count question ignores it. (3) A count above the last authored range of the two bulb services (7+) is asked.
